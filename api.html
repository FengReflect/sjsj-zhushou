09 - 脚本 API 参考（v1）

适用版本：Android App 1.9.1+（脚本宿主 API v1）
脚本目录：/data/data/com.sjsj.bot/files/scripts/<id>/main.py
目的：让第三方脚本以“插件”方式复用 App 内已经登录的连接，不需要在脚本里再登录一次。

0. 一句话理解

脚本不是独立程序，而是跑在 App 内部、拿到已登录机器人对象的一段 Python：

App 登录 → bot.gs（已连接）
              ↓
        脚本 ctx.bot / ctx.gs
              ↓
     发协议、读状态、弹窗问用户

所以：

  • ✅ 脚本里不要再调用登录、不要再 new SjsjBot、不要读 .cred_cache.json
  • ✅ 直接用 ctx.gs / ctx.send() 操作当前连接
  • ✅ 二次登录会顶掉 App 的连接，这就是之前“软件被卡掉”的原因

1. 脚本文件规范

1.1 文件头（必须）

# @name 城池孵蛋
# @version 1.0.0
# @author 你的名字
# @api 1
# @desc 一句话说明
# @entry run
字段 必填 说明
@name 是 列表显示名；编辑页名称留空时用它
@version 否 默认 1.0.0
@author 否 默认“未知”
@api 否 脚本要求的宿主 API 版本，超过 App 支持版本会拒绝保存
@desc 否 列表里的说明文字
@entry 否 入口函数名，默认 run

1.2 入口函数（必须）

def run(ctx):
    ...
  • 必须有且只有一个参数 ctx。
  • 保存时会做 ast.parse 语法检查，并检查入口函数是否存在。
  • 单文件、UTF-8、最大 256 KB。

1.3 保存与调用

  • App「脚本」页：导入 .py / 粘贴新建 → 保存后变成列表里的卡片
  • 卡片按钮：运行 / 编辑 / 删除
  • 运行中禁止删除、禁止修改当前脚本
  • 同一时间只能跑一个任务（脚本与副本/器灵互斥）

2. 运行时规则

规则 说明
后台线程 脚本在独立 daemon 线程运行，不阻塞界面
协作式停止 循环里必须调用 ctx.check_stop()；阻塞等待用 ctx.sleep()
异常隔离 脚本报错只写日志，不会让 App 崩溃
停止 点“停止当前脚本”会置停止位；正在 ctx.dungeon() 时会等本关结束
弹窗 交互 API 会阻塞脚本线程，直到用户操作完成；停止时会自动按“取消”返回
线程安全 不要在脚本里自己开线程操作 ctx.gs，协议并发会触发风控

3. ctx 完整接口

3.1 基础

接口 返回 说明

3.3 交互（仅 App 内）

接口 返回 取消时
ctx.input(title, hint="", default="", password=False) str None
ctx.input_multiline(title, hint="", default="") str None
ctx.select(title, options, default=0) int 下标 -1
ctx.confirm(title, message) bool False
ctx.alert(title, message) None —
ctx.toast(message) None 不阻塞
ctx.copy_text(text) bool 写入系统剪贴板
ctx.get_clipboard() str 读取系统剪贴板，失败返回 ""
ctx.save_text(name, content) str / None 保存到 下载/SJSJBot/，返回可读路径；失败回退 App 外部目录

说明：

  • options 传 Python 列表，元素会转成字符串。
  • password=True 时输入框内容显示为圆点。
  • 弹窗在 App 主线程显示，脚本线程等待；用户点返回键等同取消。
  • PC 端没有 UI，以上接口会记录一条日志并返回默认值（None / -1 / False），方便干跑逻辑。

示例：

def run(ctx):
    mode = ctx.select("选择模式", ["普通", "高级", "全部"], 0)
    if mode < 0:
        return

    times_text = ctx.input("孵化次数", "输入数字", "10")
    if times_text is None:
        return
    try:
        times = int(times_text)
    except ValueError:
        ctx.alert("参数错误", "次数必须是整数")
        return

    if not ctx.confirm("确认", "将孵化 %d 次，是否继续？" % times):
        return

    ctx.toast("开始孵化")
    for i in range(times):
        ctx.check_stop()
        ctx.log("第 %d/%d 次" % (i + 1, times))
        ctx.sleep(1.5)
    ctx.alert("完成", "孵化结束")

3.6 原始协议（危险）

ctx.send(proto, data)
  • proto：协议号，int
  • data：bytes 或十六进制字符串（"01 02 FF" / "0102ff" 均可）
  • 返回 gs.send 的结果；只发不收，不等服务器回复。

⚠ 使用 ctx.send / ctx.bot / ctx.gs 的脚本会在列表里标 ⚠ 原始协议。
高频发包、双弹并行等形态会触发踢线/封号，参考 03-副本战斗与风控.md。

3.7 协议级开放接口（v1.9.157 新增）

设计原则：框架只给原语，业务由开发者自己封装。不再为每个活动单独加接口——
你能对协议做的事情，这里全部开放。

3.7.1 编解码（小端，与游戏 wire 一致）

w = ctx.writer()
w.writeInt(5000).writeShort(4).writeUTF("名字").writeBoolean(True)
payload = w.bytes()

r = ctx.reader(payload)
a = r.readInt()          # 5000
b = r.readShort()        # 4
s = r.readUTF()          # "名字"
c = r.readBoolean()      # True
r.at_end()               # True
r.offset / r.remaining / r.peek(4)
写 读 宽度
writeByte readByte 1B 有符号
writeUnsignedByte readUnsignedByte 1B
writeShort readShort 2B 有符号
writeUnsignedShort readUnsignedShort 2B
writeInt readInt 4B 有符号
writeUnsignedInt readUnsignedInt 4B
writeLong / writeUnsignedLong readLong / readUnsignedLong 8B
writeFloat / writeDouble readFloat / readDouble 4B / 8B
writeBoolean readBoolean 1B
writeUTF readUTF ushort 长度 + UTF-8
writeBytes / writeHex readBytes(n) / readHex(n) / readRest() 原始字节

越界会抛 ValueError，并带上 offset 与剩余长度，便于定位协议改版。

便捷发包：

ctx.send_fields(8270, ("uint", 5000), ("uint", 4))
ctx.send_fields(30992, ("short", 1), ("int", 0))

3.7.2 监听协议

def on_packet(body):
    r = ctx.reader(body)
    score = r.readInt()

h = ctx.listen(8271, on_packet)                       # 所有 8271
h = ctx.listen(8271, on_packet, match=b"\x00\x01")     # 包体含该字节段才回调
h = ctx.listen(8271, on_packet, match=lambda b: len(b) > 8)  # 自定义判定
h = ctx.listen(8271, on_packet, once=True)             # 命中一次自动解除

ctx.unlisten(h)      # 解除单个
ctx.unlisten_all()   # 解除全部（脚本结束也会自动清理）
  • match 支持 None / bytes / hex 字符串（"00 01"）/ callable
  • 回调在接收线程执行，内部异常会被捕获并写日志，不会中断连接
  • 不会吞掉框架原有解析：注册后框架自己对该协议的处理仍会正常执行

3.7.3 等待与请求-响应

body = ctx.wait(1068, timeout=5)                    # 等一个包，超时返回 None

body = ctx.request(8274, b"", expect=8275, timeout=5)  # 发 8274 等 8275
if body is None:
    ctx.log("服务器没回包")

3.7.4 声明式自动应答

# 收到 8995 且包体含 0x01，就回 8996
ctx.auto_reply(8995, 8996, match=b"\x01", reply=b"\x00\x00")

# 动态构造回包
def build(body):
    w = ctx.writer()
    w.writeInt(len(body))
    return w.bytes()

ctx.auto_reply(8271, 8272, builder=build, once=True)

builder(body) -> bytes 优先于固定 reply。声明式规则同样遵守 match / once 语义。

3.7.5 持久化与辅助

ctx.save_state("progress", {"stage": 3})    # 跨运行保留，按脚本隔离（JSON）
ctx.load_state("progress", default={})       # 不存在返回 default
ctx.clear_state("progress")                  # 传 None 清空全部

proto, body = ctx.wait_any([8271, 8273], timeout=5)   # 多协议谁先到返回谁
ctx.sleep_jitter(1.0, 0.3)                   # 1s ±30% 随机，降低机械特征
ctx.is_online()                              # 长驻脚本自检（断线判断）
ctx.warn("提示")                              # 带 ⚠ 前缀
ctx.debug("细节")                             # 仅调试版输出，发布版静默

3.7.6 实战：自己封装一个业务操作

① 查询 + 解析（兑换次数）

def exchange_remain(ctx):
    body = ctx.request(8274, b"", expect=8275, timeout=5)
    if body is None:
        return {}
    r = ctx.reader(body)
    n = r.readInt()
    out = {}
    for _ in range(n):
        item_id = r.readInt()
        out[item_id] = r.readShort()
    return out

② 进副本（5419 直连）

def enter_dungeon(ctx, pass_id):
    w = ctx.writer()
    w.writeInt(int(pass_id))
    ctx.send(5419, w.bytes())
    body = ctx.wait(5395, timeout=8)      # 5395 = 副本开始
    return body is not None

③ 释放技能（1282）

def cast_skill(ctx, skill_id, x, y):
    w = ctx.writer()
    w.writeInt(int(skill_id))
    w.writeShort(int(x)).writeShort(int(y))
    ctx.send(1282, w.bytes())

④ 条件规则：只在特定包出现时动作

h = ctx.listen(801, lambda b: ctx.send(769, ctx.writer().writeInt(0).bytes()),
               match=b"\x04")   # 仅 dropType=4

3.7.7 注意事项

  • 打包格式为小端；writeUTF 为 ushort 长度 + UTF-8，与 readUTF/_read_utf 一致
  • 脚本结束后所有监听自动解除，无需手动清理（但长驻规则建议显式 unlisten）
  • 监听/应答只是通道，风控仍需自己控制频率；自动应答循环（A→B→A）务必用 once=True
  • 除 PK / PVP 外，所有客户端能发的协议都可以用 ctx.send + ctx.writer 复现

情况 结果

def run(ctx):
    try:
        do_work(ctx)

5. 完整示例：城池孵蛋（插件式，不登录）

下面是可运行的骨架。协议号/包体需要你按实际抓包结果替换，其余部分是标准写法。

# @name 城池孵蛋
# @version 1.0.0
# @author 我
# @api 1
# @desc 复用 App 已登录连接，按次数孵蛋
# @entry run

def run(ctx):
    info = ctx.info()
    if not info["online"]:
        ctx.alert("未上线", "请先在 App 登录，再运行这个脚本")
        return

    ctx.log("当前角色=%s uid=%s 地图=%s" % (info["role"], info["uid"], info["map"]))

    mode = ctx.select("孵蛋模式", ["普通蛋", "高级蛋", "全部"], 0)
    if mode < 0:
        ctx.log("用户取消")
        return

    text = ctx.input("孵化次数", "例如 10", "10")
    if text is None:
        return
    try:
        times = max(1, int(text))
    except ValueError:
        ctx.alert("参数错误", "次数必须是整数")
        return

    if not ctx.confirm("确认", "模式=%d，次数=%d，开始？" % (mode, times)):
        return

    for i in range(times):
        ctx.check_stop()

        # ---- 这里换成你的抓包协议 ----
        # proto, body = 抓包得到的孵蛋请求
        # ctx.send(proto, body)
        # ----------------------------

        ctx.log("第 %d/%d 次已发送" % (i + 1, times))
        ctx.sleep(2.0)          # 给服务器结算时间，同时响应停止

    ctx.toast("孵蛋完成")
    ctx.exit("孵蛋脚本结束")

要点：

  1. 不登录：ctx 拿到的就是 App 当前会话。
  2. 参数问用户：select / input 返回 Python 原生类型，直接参与逻辑。
  3. 节奏自己控：ctx.sleep 可被停止；不要用 time.sleep。
  4. 结果靠查：send 是单向的，需要结果时用 ctx.bag() / ctx.status() / ctx.soul_list() 轮询。

7. 限制与后续

当前 API v1 不支持：

  • 多文件脚本 / 第三方依赖包
  • 等待某个协议回包的 wait_for(proto)（后续可加）
  • 多选弹窗（当前只有单选）
  • 脚本参数配置页（参数用 input/select 现场问）
  • 脚本之间互相调用

8. 安全

  • 第三方脚本拥有与 App 相同的协议能力（包括 ctx.send），能绕过所有风控节奏。
  • App 首次导入会弹风险确认；脚本列表会对原始协议脚本打标。
  • 只运行你信任的脚本；脚本导致的封号、回档、装备损失无法恢复。

9. 内置插件与协议速查（v1.9.157）

9.1 天降宝箱（plugin_treasure_drop.py v2.2.0）

  • 前置：新桃源村（ctx.gs.login_mode == 1）；login_mode == 0 时提示退出，2（未知）时继续以 801 下发为准。
  • 内部协议：801 掉落物进视野、802 被拾取、8995 活动状态、8996/8997 拾取、769 移动/瞬移。
  • 逻辑：持续接收 801 → 取最近目标 → 瞬移（769 大坐标）→ 8996(id,1) → 等 3.2s → 8996(id,2)；无宝箱时等待下一批下发。
  • 停止条件：拾满 20 个 / ret ∈ {15,25,26} / 8995 活动状态归零 / 连续 5 次 ret=22 / 兜底 70 分钟。
  • ret=22 为服务器静默（非必然上限），不再立即停止。
  • 宝箱 id 为负数，发包用 <ii（等价于 writeUnsignedInt 的 wire 表示）。

9.2 星魂对对碰（plugin_minigame_ddp.py v1.0.0）

  • 无需特定场景，主城在线即可；对应客户端 CheatDuiDuiPengControl。
  • 协议：8270(score, combo) 上报分数 → 8271(当前积分, 今日积分)；8274 查兑换信息 → 8275(n, n*(itemId, remain))；8272(itemId) 兑换 → 8273(itemId, count, ret)。
  • 关键机制：上报 5000，服务端按 score/10 = 500 计入，每日上限 5000，故 10 次正好刷满。
  • 默认兑换物：12076（小彩星魂礼包），每日 1 次。
  • 8273 ret：0=成功、1=物品不存在、2=积分不足、3=已达最大兑换次数、4=背包已满。
  • 脚本会在今日积分已满时自动跳过上报，直接兑换。

9.3 锻造锤击（plugin_forge.py v2.2.0）

  • 协议：30902→30903 查询、30992(hit)→30993 锤击。
  • hit 由客户端计算，脚本固定上报 hit=1（完美命中）。
  • 30903 尾部：short duanZaoCount（-1 归一化为 0）+ int duanzaoEndTime（0=无冷却）。
